Управляемые Datasets

Превращайте определения данных в версионируемые активы с явным происхождением.

Dataset отделяет исследовательский SQL от многократно используемого контракта данных. Его стабильный идентификатор, неизменяемые версии и семантические метаданные создают контролируемую основу для отчётов, не скрывая происхождение источника.

Посмотреть контролируемую Analytics →

01

Dataset — контракт, а не переименованный результат запроса.

Dataset связывает происхождение источника и запроса, нормализованный SQL, метаданные столбцов и семантики, состояние жизненного цикла и неизменяемые DatasetVersions. SavedQuery остаётся редактируемым SQL; Report описывает аналитический замысел.

01Dataset может быть создан из выполнения SQL Console, SavedQuery, физической таблицы или контролируемого преобразования.

02DatasetColumn сохраняет известные метаданные схемы и профиля для точной версии.

03Продвижение из SQL Console согласует канонический Dataset с семантической проекцией Analytics, не объединяя границы их ответственности.

02

Версия означает точное состояние контракта.

Изменение принадлежащих Dataset SQL, соединений, источника, схемы, столбцов или метаданных столбцов создаёт новый DatasetVersion. Метрики Analytics, RLS и разрешения отчёта остаются отдельными контрактами. Существующие ReportVersions остаются закреплёнными, пока пользователь не проверит новый DatasetVersion и не сохранит новый ReportVersion.

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

03

Виртуальная версия не фиксирует строки автоматически.

Когда DatasetVersion хранит контракт актуального SQL, последующие Runs могут читать новые строки источника, используя то же определение. Для точного восстановления исторического результата необходимы хеш Run и сохранённый артефакт либо явный материализованный снимок.

04

Сравнение показывает зарегистрированное изменение, а не придуманное влияние.

Пользователи могут сравнивать нормализованный SQL, столбцы, типы и известные метаданные происхождения. Платформа не заявляет универсальный анализ последующего бизнес-влияния для отношений, которые никогда не регистрировались.

01Точные идентификаторы левой и правой версии и контракт SQL с SHA-256

02Построчное сравнение SQL с добавлениями и удалениями

03Изменения столбцов, типов, допустимости NULL и известных метаданных

04Явные состояния без изменений, изменено, добавлено, удалено и недоступно

05

Dataset и Analytics сохраняют разную ответственность.

Dataset владеет стабильным информационным активом и версиями. Analytics владеет метриками, RLS, разрешениями ресурсов, контекстом запроса и выполнением отчёта. Это разделение делает границы управления доступными для проверки.

06

Развитие является явным решением о приёмке.

Новый DatasetVersion не переводит существующие отчёты автоматически. Пользователь сравнивает контракт, проверяет измерения и метрики, предварительно просматривает сформированный запрос, а затем сохраняет новый ReportVersion, привязанный к принятому DatasetVersion. Старые ReportVersions и Runs сохраняют исходные привязки.

  1. 01

    Сравните Dataset v2 и v3.

  2. 02

    Подтвердите изменённые SQL, столбцы и типы.

  3. 03

    Откройте черновик отчёта для Dataset v3.

  4. 04

    Проверьте метаданные и скомпилируйте SQL только для чтения.

  5. 05

    Выполните предварительный просмотр в текущем контексте разрешений и RLS.

  6. 06

    Сохраните Report v6 → Dataset v3 только после приёмки.
