Datasets gobernados

Convierta definiciones de datos en activos versionados con linaje explícito.

Dataset separa el SQL exploratorio de un contrato de datos reutilizable. Su identidad estable, sus versiones inmutables y sus metadatos semánticos crean una base controlada para Reports sin ocultar el linaje de origen.

Ver la analítica controlada →

01

Un Dataset es un contrato, no el resultado renombrado de una consulta.

Dataset conecta el linaje de Source y consulta, SQL normalizado, metadatos semánticos y de columnas, estado del ciclo de vida y DatasetVersions inmutables. SavedQuery sigue siendo SQL editable; Report describe una intención analítica.

01Un Dataset puede originarse en una ejecución de SQL Console, SavedQuery, una tabla física o una transformación controlada.

02DatasetColumn registra el esquema conocido y los metadatos de perfil de la versión exacta.

03La promoción desde SQL Console alinea el Dataset canónico con la proyección semántica de Analytics sin fusionar sus límites de propiedad.

02

Una versión representa el estado exacto del contrato.

Cambiar SQL, joins, Source, esquema, columnas o metadatos de columnas controlados por Dataset crea un nuevo DatasetVersion. Las métricas de Analytics, RLS y permisos de Report siguen siendo contratos separados. Los ReportVersions existentes permanecen fijados hasta que un usuario valida el nuevo DatasetVersion y guarda un nuevo ReportVersion.

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

03

Una versión virtual no congela automáticamente las filas.

Cuando DatasetVersion almacena un contrato SQL en vivo, ejecuciones posteriores pueden leer filas más recientes del origen aunque utilicen la misma definición. Reconstruir un resultado histórico exacto requiere el hash de ejecución y un artefacto preservado, o una instantánea materializada explícita.

04

La comparación muestra cambios registrados, no impactos inventados.

Los usuarios pueden comparar SQL normalizado, columnas, tipos y metadatos de linaje conocidos. La plataforma no afirma un análisis universal del impacto de negocio aguas abajo para relaciones que nunca fueron registradas.

01Identidad exacta de las versiones izquierda y derecha, y SHA-256 del contrato SQL

02Comparación SQL consciente de líneas, con inserciones y eliminaciones

03Cambios de columna, tipo, nulabilidad y metadatos conocidos

04Estados explícitos: sin cambios, modificado, añadido, eliminado y no disponible

05

Dataset y Analytics conservan responsabilidades separadas.

Dataset controla la identidad estable del activo de datos y sus versiones. Analytics controla métricas, RLS, permisos de recursos, QueryContext y ejecución de Report. Esta distinción mantiene revisables los límites de gobernanza.

06

La evolución exige una decisión de aceptación explícita.

Un nuevo DatasetVersion no hace avanzar silenciosamente los Reports existentes. El usuario compara el contrato, valida dimensiones y métricas, previsualiza la consulta generada y guarda un nuevo ReportVersion vinculado al DatasetVersion aceptado. Los ReportVersions y ejecuciones anteriores conservan sus vinculaciones originales.

    Comparar Dataset v2 con v3.

  2. 02

    Confirmar los cambios de SQL, columnas y tipos.

  3. 03

  4. 04

Perspectivas relacionadas

Analítica controlada Fije el contrato de datos. Gobierne la ejecución. Explique el resultado.

La analítica controlada vincula un Report con DatasetVersion exactas, valida el contexto de consulta en el servidor y conserva los permisos, RLS, filtros, vinculaciones y artefactos que explican un resultado admitido.

→ Calidad de datos Haga de la calidad parte de la ejecución, no un documento posterior.

La calidad de datos convierte expectativas orientadas a Source en aserciones SQL repetibles, con una condición de aprobación clara, un QualityRun preservado y evidencia de fallo acotada.

→ Entrega de analítica gobernada Explique por qué cambió un resultado.

Distintas definiciones y versiones de entrada pueden producir informes contradictorios para la misma pregunta.
