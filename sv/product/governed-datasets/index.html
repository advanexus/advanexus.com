Styrda Dataset

Omvandla datadefinitioner till versionshanterade tillgångar med uttrycklig lineage.

Dataset skiljer utforskande SQL från ett återanvändbart datakontrakt. Dess stabila identitet, oföränderliga versioner och semantiska metadata skapar en kontrollerad grund för rapporter utan att dölja källans lineage.

Se kontrollerad Analytics →

01

Ett Dataset är ett kontrakt, inte ett omdöpt query-resultat.

Dataset kopplar samman source- och query-lineage, normaliserad SQL, kolumnmetadata, semantiska metadata, livscykeltillstånd och oföränderliga DatasetVersions. SavedQuery förblir redigerbar SQL; Report beskriver analytisk avsikt.

01Ett Dataset kan härröra från en körning i SQL Console, SavedQuery, en fysisk tabell eller en kontrollerad transformering.

02DatasetColumn registrerar kända schema- och profilmetadata för den exakta versionen.

03Publicering från SQL Console samordnar det kanoniska Dataset med den semantiska Analytics-projektionen utan att slå samman deras ägargränser.

02

Version betyder exakt kontraktstillstånd.

När Dataset-ägd SQL, joins, Source, schema, kolumner eller kolumnmetadata ändras skapas en ny DatasetVersion. Analytics-mått, RLS och rapportbehörigheter förblir separata kontrakt. Befintliga ReportVersions förblir bundna tills en användare validerar den nya DatasetVersion och sparar en ny ReportVersion.

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

03

En virtuell version fryser inte automatiskt rader.

När en DatasetVersion lagrar ett aktuellt SQL-kontrakt kan senare körningar läsa nyare källrader med samma definition. Exakt återskapande av historiska resultat kräver körningshash och bevarad artefakt eller en uttrycklig materialiserad snapshot.

04

Jämförelse visar registrerad förändring, inte påhittad påverkan.

Användare kan jämföra normaliserad SQL, kolumner, typer och kända lineage-metadata. Plattformen gör inga anspråk på universell analys av nedströms affärspåverkan för relationer som aldrig registrerades.

01Exakt vänster/höger versionsidentitet och SHA-256 SQL-kontrakt

02Radmedveten SQL-jämförelse med tillägg och borttagningar

03Ändringar i kolumn, typ, nullable-tillstånd och kända metadata

04Uttryckliga tillstånd för oförändrat, ändrat, tillagt, borttaget och otillgängligt

05

Dataset och Analytics har separata ansvarsområden.

Dataset äger den stabila datatillgången och versionerna. Analytics äger mätvärden, RLS, resursbehörigheter, Query Context och rapportkörning. Distinktionen håller styrningsgränserna överblickbara.

06

Utveckling är ett uttryckligt acceptansbeslut.

En ny DatasetVersion flyttar inte befintliga rapporter i tysthet. Användaren jämför kontraktet, validerar dimensioner och mått, förhandsgranskar genererad query och sparar sedan en ny ReportVersion bunden till den godkända DatasetVersion. Äldre ReportVersions och körningar behåller sina ursprungliga bindningar.

  1. 01

    Jämför Dataset v2 med v3.

  2. 02

    Bekräfta ändrad SQL, ändrade kolumner och typer.

  3. 03

    Öppna rapportutkastet mot Dataset v3.

  4. 04

    Validera metadata och kompilera read-only SQL.

  5. 05

    Kör preview under aktuell behörighets- och RLS-kontext.

  6. 06

    Spara Report v6 → Dataset v3 först efter godkännande.

Fortsätt utforska

Relaterade perspektiv

Kontrollerad analys Lås datakontraktet. Styr körningen. Förklara resultatet.

Kontrollerad Analytics binder en rapport till exakta DatasetVersions, validerar Query Context på servern och bevarar behörighets-, RLS-, filter-, bindnings- och artefaktkontexten bakom ett stött resultat.

→ Data Quality Gör kvalitet till en del av körningen, inte ett dokument i efterhand.

Data Quality omvandlar källorienterade förväntningar till upprepningsbara SQL-kontroller med ett tydligt godkännandekriterium, en beständig QualityRun och avgränsad evidens vid fel.

→ Styrd analysleverans Förklara varför ett resultat ändrades.

Olika definitioner och indataversioner kan ge motstridiga rapporter på samma fråga.
