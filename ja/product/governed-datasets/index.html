ガバナンスされた Dataset

データ定義を、明示的なリネージュを持つバージョン管理資産へ変換します。

Dataset は探索用の SQL と再利用可能なデータ契約を分離します。安定した識別情報、不変のバージョン、セマンティックなメタデータにより、ソースリネージュを隠さずに Report の制御された基盤を作ります。

制御された Analytics を見る →

01

Dataset は契約であり、名前を変えたクエリ結果ではありません。

Dataset はソース/クエリリネージュ、正規化された SQL、列/セマンティックなメタデータ、ライフサイクル状態、不変の DatasetVersion を接続します。SavedQuery は編集可能な SQL のままで、Report は分析上の意図を表します。

01Dataset は SQL Console 実行、SavedQuery、物理的なテーブル、制御された変換から作成できます。

02DatasetColumn は対象バージョンに対する既知のスキーマ／プロファイルメタデータを記録します。

03SQL Console 昇格は所有責任境界を統合せず、カノニカルな Dataset を Analytics セマンティックな投影に整合させます。

02

バージョンは契約の正確な状態を表します。

Dataset 所有の SQL、結合、Source、スキーマ、列、列メタデータを変更すると新しい DatasetVersion が作成されます。Analytics 指標、RLS、Report 権限は別契約のままです。既存 ReportVersion は、利用者が新しい DatasetVersion を検証して新しい ReportVersion を保存するまで固定され続けます。

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

03

仮想バージョンは行を自動的に固定しません。

DatasetVersion が稼働中の SQL 契約を保存する場合、後続の実行は同じ定義で新しいソース行を読み取れます。正確な過去の結果再構築には実行ハッシュと保持された成果物、または明示的なマテリアライズされたスナップショットが必要です。

04

比較は記録された変更を示し、推測した影響を作りません。

利用者は正規化された SQL、列、型、既知のリネージュメタデータを比較できます。プラットフォームは、未記録関係に対する一律の下流の業務影響分析を主張しません。

01正確な左側の/右側のバージョン識別情報と SHA-256 SQL 契約

02追加／削除を示す行を認識する SQL 比較

03列、型、NULL 許容、既知のメタデータの変更

04未変更の、変更済みの、追加済みの、削除済みの、利用できないの状態を明示

05

Dataset と Analytics は責任を分離して保ちます。

Dataset は安定したデータ資産とバージョンを所有します。Analytics は指標、RLS、リソース権限、Query Context、Report 実行を所有します。この区別によりガバナンス境界を確認できます。

06

発展は明示的な受入判断です。

新しい DatasetVersion が既存の Report を黙って移動することはありません。利用者は契約を比較し、ディメンション／指標を検証し、生成されたクエリをプレビューしてから、受け入れ済みの DatasetVersion に紐付けられたされた新しい ReportVersion を保存します。以前の ReportVersion と実行は元のバインディングを保持します。

  1. 01

    Dataset v2 と v3 を比較します。

  2. 02

    変更された SQL、列、型を確認します。

  3. 03

    Dataset v3 に対する Report 下書きを開きます。

  4. 04

    メタデータを検証し、読み取り専用の SQL をコンパイルします。

  5. 05

    現在の権限／RLS コンテキストの下でプレビューします。

  6. 06

    受入後にだけ Report v6 → Dataset v3 を保存します。

関連する視点

制御された Analytics データ契約を固定する。実行をガバナンスする。結果を説明する。

制御された Analytics は、Report を正確な DatasetVersion に結び付け、Query Context をサーバー上で検証し、対応済み結果の背後にある権限、RLS、フィルター、バインディング、アーティファクトのコンテキストを保持します。

→ データ品質 品質を、実行後の文書ではなく実行そのものの一部にします。

Data Quality は Source 指向の期待値を、明確な合格条件、永続化された QualityRun、制限された失敗証拠を持つ再実行可能な SQL アサーションへ変換します。

→ ガバナンスされた Analytics 提供 結果が変わった理由を説明する。

定義や入力の版が異なると、同じ業務上の問いにも食い違う報告が生まれます。

advanexusのこの機能は何をしますか？

Dataset は探索用の SQL と再利用可能なデータ契約を分離します。安定した識別情報、不変のバージョン、セマンティックなメタデータにより、ソースリネージュを隠さずに Report の制御された基盤を作ります。

利用前に何を確認すべきですか？

正確な過去行には、保持された結果アーティファクトまたは明示的なマテリアライズドスナップショット契約が必要です。
