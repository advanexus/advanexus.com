advanexus Intelligence

Turn a business question into a useful next step.

Ask about the selected data or task in your own words. Get explanations, SQL drafts and proposed next steps based on permitted context, while platform checks govern what can be executed.

01

Continue the same question as your work progresses.

Your workspace and side panel share your private conversations, goals and processing history. Questions may concern the platform, a project or one selected object. Rename, pin, export, feedback and memory functions are available for integration, although not all appear in every browser view.

02

Start with the selected data and your current access.

The platform checks who is asking, their organisation, project and row-level access. Intelligence receives the approved page context and selected-object references. It does not read arbitrary screen content, editor text or result grids.

01Your identity, organisation, active project and current access

02The page you are using and the exact selected object

03Limited source, SQL and metadata context with sensitive details removed

04Tools that are available under the current configuration and rules

03

Match the assistance to the task, not a different set of permissions.

Versioned guidance selects the relevant instructions and permitted tools for a request. Central rules use the configured model and define the scope of work. Different kinds of assistance do not create separate permissions or require users to choose a model.

04

Review the proposal before an action changes anything.

The assistant can explain, draft or request an available tool. The platform checks the tool, its inputs, scope and rules again. Data previews and changes follow the confirmation or approval required for that particular action.

Goal → Grounded context → Proposal → Validation → Confirmation or approval → Action → Evidence

05

Use the same application controls, whether a person or AI starts the work.

AI requests use the existing SQL, Dataset, Analytics, Assurance and Service Desk services. An explanation can be a complete answer, but a claim that something changed requires a completed action or tool result recorded by the responsible module.

01Sources and SQL Console: inspect metadata, check SQL, preview within approved limits and save a query.

02Datasets, Data Quality and Analytics: find the exact resource, guide analysis and make only explicitly supported, controlled changes.

03ANpy: check the structure of suggested Python code on the server; the assistant does not execute notebook cells.

04Assurance and Service Desk: search within permitted scope and use supported case, evidence-package or ticket actions.

06

Get a SQL draft for the database you actually selected.

For an analysis or dataset request, Intelligence uses the selected permitted source, schema and metadata. It explains what each row represents, the dimensions, metrics and chart suggestion, and checks the SQL for that database before display or preview. A draft is not proof that a query ran.

07

Follow progress without losing the saved processing history.

In asynchronous mode, the request is saved in the queue before processing begins. Progress is shown live or through periodic updates, while recorded events remain the source of truth. Stop, Regenerate, recovery of stalled work and protection against late results follow the same request history.

08

Manage capacity and understand recorded usage.

Before contacting the model provider, the platform checks concurrent requests and request rates. Versioned policies can set limited or unlimited token capacity globally, per organisation or per user. Usage and attributed costs are recorded; this is not a guaranteed spending ceiling or coordination across regions.

09

Keep assistance within the actions that are available today.

Intelligence does not search the web, operate a browser, read arbitrary screens or run an unrestricted autonomous workflow. It can use only available tools and never gains data or permissions that the current user lacks.

01Drive, Sandbox and workflow preparation provide explanations only where no execution connection is implemented.

02Starting, retrying or cancelling Pipelines and running Data Quality rules are not currently available AI actions.

03Analytics changes are limited to an explicitly confirmed table-report draft for one exact dataset version, not general chart or dashboard creation.

04Automatic retrieval from documentation, separate model-provider accounts per organisation, fixed spending caps and a complete retention/legal-hold interface are not currently available.

10

Understand the suggestion and the evidence behind it.

An answer should use the selected source or object, distinguish facts from assumptions and provide checked SQL when requested. It explains what is being measured and why it is useful. Missing context must remain visible rather than being filled with invented data.

11

Shorten the path from question to action. Keep approval with people.

advanexus Intelligence explains permitted information and proposes an available next step.

The model does not approve its own changes. Platform checks validate the proposal, policies and authorised people govern changes, and the responsible module records what actually happened.

Business goal → Permitted context → AI proposal → Deterministic validation → Human authority → Registered action → Result and evidence
