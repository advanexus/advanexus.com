01

النطاق والهوية

يمثل Tenant حدود المؤسسة وعزل البيانات. ويمثل Project نطاق العضوية والتنفيذ داخل المستأجر. ويمثل Actor هوية المستخدم أو الخدمة أو النظام المحكوم والمعروف والمرتبط بإجراء.

سجل الجلسات

سجل يملكه الخادم ويُستخدم للتحقق من JTI المصادق عليه والجهة الفاعلة والمستأجر وProject النشط والعمر وحالة الإلغاء.

نطاق الصلاحيات

العمليات والمشاريع الفعالة التي يجوز للجهة الفاعلة الحالية استخدامها بعد الحل على جانب الخادم.

02

البيانات والإصدار

يمثل Source هوية اتصال محكومة. وتمثل Dataset عقد بيانات ثابتاً ومحكوماً. ويمثل Version حالة غير قابلة للتغيير لملف أو جدول أو Dataset أو Report أو دفتر أو كائن آخر ذي إصدارات.

FileVersion وTableVersion

هوية ملف مصدر غير قابلة للتغيير ونشر جدول مادي مُدار وغير قابل للتغيير، على التوالي.

DatasetVersion

عقد SQL ومخطط وأعمدة غير قابل للتغيير ومملوك لـDataset؛ ولا يجمّد الإصدار الافتراضي الصفوف الحية بالضرورة.

ReportVersion

قصد تحليلي غير قابل للتغيير وربط دقيق بـDatasetVersion معتمد لعمليات AnalyticsRun اللاحقة.

03

التنفيذ والنتيجة

يمثل Run محاولة تنفيذ ونتيجة ملموستين. ويمثل Artifact مخرجاً محدوداً ومحفوظاً ومرتبطاً بالتشغيل. وتغير مرشحات وقت التشغيل سياق التنفيذ، بينما يفرض أمن مستوى الصفوف الذي يملكه الخادم رؤية البيانات.

QueryExecution

محاولة تنفيذ واحدة لخدمة SQL Console مع سياق Source وSQL والنجاح أو الفشل.

AnalyticsRun

تنفيذ واحد لتقرير مع عمليات ربط دقيقة للإصدارات وسياق المرشحات والصلاحيات وأمن مستوى الصفوف والتشخيصات والأصول.

CellRun

تنفيذ واحد لخلية شفرة ANpy مرتبط بإصدار الدفتر والبيئة وجيل النواة.

04

الأدلة والتحقيق

يمثل Evidence الجهة الفاعلة والنطاق والتغيير والسياق والنتيجة التي يستطيع المصدر المرجعي دعمها. وتمثل Finding حالة مدعومة تتطلب المراجعة. وتنظم Case التحقيق البشري من دون تغيير حدث المصدر.

Evidence Package

تصدير تقني محدود وخاضع لفحص الصلاحيات مع بيانات وصفية للنطاق والبيان ومجموع التحقق؛ ولا يكون تلقائياً موقعاً رقمياً أو حاسماً قانونياً.

تذكرة Service Desk

سجل تواصل تشغيلي على مستوى المستأجر قد يكون Project فيه سياقاً اختيارياً لا شرط التفويض.

05

Assurance والسلامة

يمثل Assurance طبقة القراءة والتحقيق المدركة للصلاحيات. ويمثل الإسقاط عرضه المطبع القابل لإعادة البناء. وتصف السلامة قوة التحقق، بينما تقيّم قابلية إعادة الإنتاج معايير صريحة بدلاً من درجة ثقة غير مفسرة.

المصدر المرجعي

الوحدة التي تملك السجل الموثوق المستخدم في مسار عمل مدعوم.

الإسقاط

نموذج قراءة Assurance قابل لإعادة البناء ومُنشأ من أحداث ولقطات ومحولات تاريخية مرجعية ومدعومة.

Turn وAction في Intelligence

قد تكتمل Turn باستجابة، بينما يسجل Action أثراً جانبياً مسجلاً ومقترحاً أو منفذاً ضمن عقد التأكيد والموافقة الخاص به.

باختصار

ما هو advanexus؟

advanexus هو نظام التحكم والأدلة للتنفيذ الحرج في المؤسسات عبر الأنظمة وتدفقات البيانات والأتمتة والإجراءات المسجلة المدعومة بالذكاء الاصطناعي. وهو يربط السياق والقواعد والصلاحية والتنفيذ والنتيجة والاستعادة والأدلة المتاحة في نموذج تشغيل محدد النطاق.

هل يمكن إعادة إنتاج النتيجة وتفسيرها لاحقاً؟

يحفظ advanexus العقود الدقيقة وسياق التنفيذ حيث تدعم القدرة ذلك، ثم يقيّم معايير صريحة لقابلية إعادة الإنتاج. ويبلغ عن نتيجة قابلة لإعادة الإنتاج أو قابلة جزئياً أو غير قابلة أو غير مقيّمة بدلاً من الوعد بإعادة تشغيل عامة.

تقدّم يبقي كل شيء مترابطاً.

يجمع اسم advanexus بين advance و nexus: التقدّم من دون قطع الصلة بين البيانات والقرارات والمساءلة والأدلة.
