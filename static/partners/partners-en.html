02 / Problem and need

Teams manually assemble an answer
from data held in different systems.

They need a connected workflow showing what was checked, what is missing and whether the result meets the conditions for the next step.

THE OPERATIONAL PROBLEM
WHAT IS NEEDED

Each system shows its part of the work

The team must establish which records and period the answer covers.

One answer to the same business question

Connect relevant records and make the scope of the review explicit.

Successful processing does not establish completeness

A transfer can finish while the report still lacks required data.

A check before the next step

Check the agreed condition and stop the configured workflow when it is not met.

An exception starts another investigation

The team searches again for the rule, version and outcome of the previous attempt.

Preserved context for the decision

Link the finding to available evidence and determine the permitted next step.

Sources

Supported sources become available for authorised work without replacing their systems of record.

Partner opportunity

Select sources and validate connectivity, available operations, network access and permissions.

Example use

Connect the relevant business records for a shared check, using the minimum required permissions.

Capability boundary. Capabilities are not identical across connectors. Read, write, transfer and other operations are checked for the specific source and environment.

Public description and scope

SQL Console

An analyst investigates a specific business question and prepares a query or result for reuse.

Partner opportunity

Explore the data, define the business logic and review which information the query returns.

Example use

Prepare a query for records missing a required mapping before the next workflow step.

Capability boundary. Dialect, available operations, export and execution depend on the selected source and permissions. A query does not automatically become a persistent business rule.

Public description and scope

Sandbox & ANpy

Files and specialised analyses gain an organised working environment and recorded executions.

Partner opportunity

Prepare specialised processing, the analytical method, input data and expected outputs.

Example use

Repeat an approved Python analysis against an agreed input and inspect its execution outcome.

Capability boundary. Runtime, libraries, network access and data handling are validated in the target environment. This is not a promise of unrestricted code execution.

Public description and scope

Pipelines & orchestration

Recurring jobs are connected in a defined sequence, with scheduling and a visible outcome.

Partner opportunity

Translate the business process into steps, dependencies, schedules and conditions for proceeding or stopping.

Example use

Data preparation → required check → the next step only after its condition is met.

Capability boundary. Stopping applies to the configured workflow and supported steps. It does not automatically stop unrelated processes in external systems.

Public description and scope

Data Quality

Explicit rules check whether data meets agreed conditions before the workflow proceeds.

Partner opportunity

Define acceptance criteria, finding severity and what should happen when a rule fails.

Example use

A required mapping, expected record count or permitted set of values within the agreed scope.

Capability boundary. Automatic data repair is not promised. Blocking rules and authorised corrections are defined separately.

Public description and scope

Monitoring

Business checks bring relevant records together and identify specific exceptions for review.

Partner opportunity

Design domain-specific checks, reconciliation and a business-relevant view of priorities.

Example use

Compare transport status, warehouse records and delivery confirmation without treating them as equivalent.

Capability boundary. A finding supports only the returned scope. Missing evidence, an open question and a confirmed failure are not the same.

Public description and scope

Datasets

Dataset definitions and saved versions make the basis of an analysis explicit.

Partner opportunity

Define trusted datasets, the business meaning of fields, scope and reuse.

Example use

Keep a known definition version for a report and inspect which input the result relies on.

Capability boundary. A definition version does not mean every source table is permanently copied. Materialisation, retention and linked relationships have defined boundaries.

Public description and scope

Analytics & Visualizations

Results become views and metrics that make sense at different levels of decision-making.

Partner opportunity

Define metrics, business interpretation, filters and views for leadership, managers and operations.

Example use

Present one process through result readiness, exception scope and the affected records.

Capability boundary. The analytical path and dialect depend on the supported environment. Permissions and available data determine what can be displayed.

Public description and scope

Assurance

Review who did what, against which version and with what outcome, within the available evidence.

Partner opportunity

Agree evidence needs, review criteria and support for investigation and handover.

Example use

Connect a question about a result to the available execution record, rule and relevant version.

Capability boundary. Available evidence does not guarantee complete history, universal replay, legal conclusiveness or certification.

Public description and scope

Intelligence

Users can more easily find and understand permitted information and prepare supported next steps.

Partner opportunity

Select valuable use cases, approved resources, access boundaries and user training.

Example use

Use an approved AI application to request a permitted check and explain the returned result within its scope.

Capability boundary. An AI proposal is not execution evidence. Permitted actions depend on the supported client, connection, resources and permissions; access is not unrestricted.

Public description and scope

AI Control & Evidence

Connected AI applications receive approved resources, fields and operations, with visibility into access and execution.

Partner opportunity

Define with the customer what is shared, with which connection and for which business task.

Example use

Approve a project-specific check, then read the result of that same execution from an AI conversation.

Capability boundary. Project approval and individual connection permission are separate. Source metadata does not grant access to all business rows.

Public description and scope

Service Desk

A support request, its conversation and status stay together instead of being scattered across messages.

Partner opportunity

Agree the support channel, accountable roles and evidence needed to investigate an issue.

Example use

Include an execution reference in a support request and follow the response and status in the same thread.

Capability boundary. The support channel is organisation-wide, not project-isolated. It is not an automated SLA, escalation or complete ITSM system.
