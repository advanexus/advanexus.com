ANpy 受治理的 Python

在项目范围运行时中开展受控 Python 工作。

ANpy 为 Python 分析提供已知环境、笔记本修订、内核生命周期和 CellRun 记录，同时让生产隔离与软件包策略处于平台控制之下。

探索 ANpy 契约 →

01

环境是分析身份的一部分。

依赖要求会依据已批准离线软件包目录进行规范化，并与 Python／运行时配置及 SHA-256 身份一同存储。失败候选不会替换先前就绪环境。

01依赖要求可以粘贴或上传到环境契约。

02软件包解析固定且离线针对已批准目录执行；不允许任意互联网安装。

03工作区、Python 版本、规范化的依赖要求与运行时配置共同生成稳定环境身份。

02

笔记本状态按修订管理，不会静默覆盖。

权威 nbformat 4 文档使用明确手动保存和强 ETag 处理并发写入。检查点与恢复会创建不可变版本，而已保存笔记本头仍是明确可变修订。发生冲突时会保留本地草稿，并要求用户选择重新加载或重新应用路径。

03

内核生命周期在浏览器之外受控。

可信 runtime-manager 会在启动、中断、重启或停止之前验证工作区、笔记本和环境身份。浏览器输入不能选择主机路径、容器或控制凭据。

04

安全回放不是内存快照。

启动新内核后，只有当修订、源哈希、环境与运行证据一致时，有限回放才会重建先前成功且未变更的设置单元。过期或不完整证明会安全关闭。

01停止与重启不会持久化 Python 进程内存。

02符合条件且未变更的前置单元可以在新内核代次中回放。

03来源或环境变更以及前置证据不完整都会阻止回放，而不是猜测命名空间状态。

05

CellRun 让代码执行受到限制且可检查。

每个已提交 CODE 单元都会保留来源身份、笔记本修订、环境与内核上下文、有限 stdout/stderr 元数据、持续时间和终态。当前浏览器没有实时 stdout 流，也没有完整 DataFrame/图表渲染器。

06

ANpy 保持当前边界可见。

选择获准的Drive文件或共享文件，绑定其版本，并将其准备为笔记本的只读输入。这需要配置好的运行环境，不会自动开放所有项目文件或外部系统的访问权限。
