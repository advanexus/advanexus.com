运营指南 · 版本演进

在不改写历史的前提下演进 Dataset 与报告。

当 Dataset 拥有的 SQL、来源血缘、架构、列或列元数据发生变化，且现有报告必须决定是否接受新契约时，请使用此工作流。

01

决策问题

Dataset v3 是否保留报告所需的列、类型、粒度和来源含义？还是 Report v5 应继续固定到 Dataset v2，直到重新设计分析契约？

02

使用的对象与控制

Dataset、DatasetVersion 与 DatasetColumn 承载基础数据契约。ReportVersion 承载分析意图和准确 DatasetVersion 绑定。AnalyticsRun 记录当前治理下的一次执行。

01Dataset 生命周期与不可变 DatasetVersion 身份

02规范化 SQL、来源血缘、列、类型与已知概要元数据

03Report 维度、指标、图表、持久筛选器与准确绑定

04服务器拥有的编译、权限、RLS 与预览上下文

03

接受流程

新的 DatasetVersion 绝不会自行移动现有 ReportVersion。

  1. 01

    创建新的 DatasetVersion

    保存已变更且由 Dataset 拥有的 SQL/架构/列契约，同时保留稳定 Dataset 身份和所有先前版本。

  2. 02

    比较准确版本

    审阅规范化 SQL 差异、来源血缘、新增/移除/变更列、类型、可空状态和不可用历史元数据。

  3. 03

    评估分析兼容性

    确认每个指标所需的目标粒度、维度和来源字段；不要仅根据名称匹配推断兼容性。

  4. 04

    打开新的报告草稿

    保持先前 ReportVersion 不可变，并将草稿绑定到候选 DatasetVersion。

  5. 05

    验证并编译

    解析元数据，验证 Query Context，并为当前受支持方言路径编译服务器拥有的只读 SQL。

  6. 06

    在治理上下文中预览

    在当前权限与 RLS 范围内执行有限预览并审阅诊断，而不是只接受架构验证。

  7. 07

    保存已接受的 ReportVersion

    只在接受后持久化新绑定；后续 AnalyticsRun 指向该准确 ReportVersion 与 DatasetVersion 对。

04

失败与部分路径

候选被拒绝后，先前面向生产的报告版本及其历史运行绑定保持不变。

字段被移除或更改

编译或语义验证会阻止草稿；应重新设计维度或指标，而不是更改旧 ReportVersion。

预览出现意外差异

把实时行漂移、来源变更、筛选器/RLS 范围和契约变更视为独立假设；虚拟 DatasetVersion 不是数据行快照。

多绑定为部分状态

审阅每个绑定诊断并保留部分状态；不要只根据成功绑定认证报告。

05

生成的证据

版本比较、已接受 DatasetVersion 身份、不可变 ReportVersion 绑定、编译/配置/筛选器/RLS 哈希以及后续 AnalyticsRun，为受支持变更提供已记录链。

Report v4 → Dataset v2 · Report v5 → Dataset v2 · Report v6 → Dataset v3

06

当前边界

比较涵盖已记录 SQL、架构、列、元数据与血缘；不会虚构通用下游业务影响。Analytics 指标、RLS 和报告权限仍位于基础 Dataset 聚合之外，准确历史行需要制品或明确物化快照契约。

简明解答

结果能否在以后复现并解释？

在能力支持的范围内，advanexus 保留精确契约与执行上下文，并评估明确的可复现标准。它报告可复现、部分可复现、不可复现或未评估，而不是承诺通用重放。

advanexus 保留哪些证据？

根据受支持模块，系统可以连接主体、版本、执行、质量决定、结果、工件、Findings、Cases 以及可通过校验和验证的 Evidence Packages。来源强度与缺失证据保持可见；证据包不会自动成为数字签名、WORM 记录或法律结论。

保持连接，持续向前。

advanexus 融合 advance 与 nexus：向前迈进，同时不断开数据、决策、责任与证据之间的连接。
